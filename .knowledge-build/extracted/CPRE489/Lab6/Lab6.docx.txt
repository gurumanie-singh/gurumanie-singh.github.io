CPR E 4890: Computer Networking and Data Communication
Lab Experiment #6 – CloudLab Experiment: IPv4 Routing Basics
Summary
In this lab I was able to gain some experience with static IPv4 routing using CloudLab. The lab involved working with a three-node network topology where each node was connected to two of three subnets, meaning no single node could initially reach all the addresses in the network. By using the route -n command, I was able to find each node's routing table and noted that only directly connected subnets were known to each node by default. This made it pretty clear as to why certain ping and traceroute attempts were failing before any manual configuration (for example, Node A).
In Exercise 2, I was able to review (again) how to manually add static routes using the route add command (already learned in CPRE431 too). We needed to specify a destination subnet, netmask, gateway IP, and outgoing interface. By updating the routing tables on all three nodes, I was able to gain connectivity across the entire network. The traceroute outputs were fun to watch and quite useful in being able to see the path packets took through the intermediate nodes.
