Exercise 1: Generate Data 
1. On the client, enable the tcp_probe tracepoint and set it to monitor traffic to/from TCP port 5001:  
 
echo "sport == 5001 || dport == 5001" | sudo tee /sys/kernel/tracing/events/tcp/tcp_probe/filter 
echo 1 | sudo tee /sys/kernel/tracing/events/tcp/tcp_probe/enable 
 
2. On the server, run 
 
iperf -s 
 
3. On the client, run 
 
sudo cat /sys/kernel/tracing/trace_pipe | tee /tmp/tcpprobe.dat 
 
4. Open another SSH session to the client and run  
 
iperf -t 60 -c server -P 3 
 
5. Wait for iperf to complete on the client. It will take about a minute. In the window where 
trace_pipe is running, you should see a line of output for each TCP packet. Take screenshots of 
the trace and iperf output for the running results. (10 points)

2 
 
6. After iperf completes, press Ctrl+C in the trace_pipe window to stop recording. The output will be 
saved in /tmp/tcpprobe.dat on the client. Use the following scp command from your local machine 
to transfer tcpprobe.dat for processing. Substitute your username or net ID for netid, the node’s 
host name for hostname, and the SSH port number for port. 
 
scp -i <private_key> -P <port> <netid>@<hostname>:<file_location> <dest_location> 
 
Example: 
scp -i <private_key> -P <port> <netid>@<hostname>:/tmp/tcpprobe.dat ./tcpprobe.dat 
 
Note: The client port number may not be specified in Cloudlab. In such cases, the -P <port> option may 
be omitted. 
 
The tcp_probe tracepoint records a line of output every time a packet is sent, if either the destination or 
source port number in the TCP packet header is 5001 (since we set the filter to port 5001). Each line of 
output includes the following fields in key=value format: 
 
Field  
Explanation  
Time  
Time (in seconds) since beginning of probe output  
Source  
Source address and port of the packet, as IP:port  
Destination  
Destination address and port of the packet, as IP:port  
Bytes  
Bytes in packet  
Next  
Next send sequence number, in hex format  
Unacknowledged  Smallest sequence number of packets sent but unacknowledged, in hex format  
cwnd  
Size of send congestion window for this connection (in MSS)  
ssthresh  
Slow-start threshold for this connection (in MSS)  
Send window  
Send window size (in MSS) – set to the minimum of send CWND and receive window size  
Smoothed RTT  
Smoothed estimated RTT for this connection (in ms)  
Receive window  Receiver window size (in MSS), received in the last ACK. This limit prevents the receiver 
buffer from overflowing, i.e., prevents the sender from sending at a rate that is faster 
than the receiver can process the data. 
 
Note: The output format uses key=value pairs (e.g., snd_cwnd=10 ssthresh=2147483647). Each line also 
includes a timestamp, process name, and CPU number at the start. To extract a specific field for plotting, 
use grep or awk (e.g., grep -oP 'snd_cwnd=\K\d+' tcpprobe.dat).
