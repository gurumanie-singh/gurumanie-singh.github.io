In this lab, I was able to get some hands-on experience with the FAT-12 filesystem and was able to understand more about how this lab connects to the lectures. I also learned that the FAT-12 filesystem stores metadata in a very specific layout by starting at the logical sector 0. The boot sector also contains some critical information such as the bytes per sector, sectors per cluster, and the number of FAT tables. I was also able to refresh on little endian byte ordering, where multi-byte values are stored with the Least Significant Byte (LSB) first. This required some pretty careful conversion when it came to reading the 2 byte and 4 byte values. By implementing these programs in the lab to read and parse these structures, I was able to understand how operating systems interpret raw disk data to extract meaningful filesystem information.

The second part of the lab taught me how the directory entries are structured in the FAT-12 filesystem. Each entry occupies exactly 32 bytes which contain the filename, attributes, timestamps, and file size. I was able to learn how to parse these different fields such as the file attributes (read-only, hidden, system, archive) and how time and date are encoded using the specific bit ranges. Furthermore, invalid entry markers such as 0x00 for end of entries and 0xE5 for deleted files showed me how filesystems manage how files are deleted without overwriting any data. This lab was quite fun and provided me valuable insights into low level filesystem operations and how the higher level commands like "ls" are implemented. I always thought the "ls" was low level enough until I did this lab.
